Automated Upgrade Workflow — Step by Step

When a user types "Upgrade this cluster to 4.14.28" in the AI Chat, the following 13-step workflow executes automatically:

1
User Request & Intent Recognition
User Action
User types a natural language upgrade request in the AI Chat interface.
  • AI parses the message and identifies the upgrade intent and target version
  • Extracts version number (e.g., 4.14.28) from free-form text
  • Confirms cluster context from the active workspace selection
Instant
2
Version Validation & Path Verification
AI Powered
AI validates the target version exists and the upgrade path is supported.
  • Queries ClusterVersion to get current version
  • Checks the upgrade channel graph for valid paths
  • Detects EUS-to-EUS upgrades and validates intermediate hops
  • Confirms target version is available in the configured channel
~30 seconds
3
Pre-Assessment — 50+ Health Checks
AI Powered
AI runs a comprehensive cluster health assessment in parallel before touching anything.
  • Cluster Operators — all available, not degraded, not progressing
  • Node Health — all Ready, no resource pressure, no cordoned nodes
  • etcd — quorum, member count, leader stability, DB size
  • Certificates — check expiry within upgrade window
  • Deprecated APIs — scan for removed APIs in target version
  • Storage — PV capacity, CSI drivers, StorageClass health
  • Pod Disruption Budgets — validate PDB configuration
  • Networking — SDN/OVN, DNS, ingress controllers
  • Machine Config Pools — sync status, paused pools
2–3 minutes
4
Component Analysis & Blocker Identification
AI Powered
AI analyzes health check results and identifies any blockers that must be resolved before upgrade.
  • Classifies each finding as Blocker, Warning, or Info
  • Assigns risk scores to each component
  • Generates an overall upgrade readiness score
  • Produces PDF and HTML assessment reports
~1 minute
5
Remediation Proposals
AI Powered
For any blockers found, AI proposes targeted fix actions with risk scoring.
  • Each blocker gets a specific remediation action (e.g., "restart degraded operator", "renew certificate")
  • Fix proposals include risk level and impact assessment
  • User can review and approve fixes via the UI before proceeding
  • If no blockers found, this step auto-advances
~30 seconds
6
ServiceNow Change Request Creation
Automated
System auto-generates a fully populated ServiceNow Change Request with all required artifacts.
  • CR populated with: description, justification, risk classification, rollback plan, implementation steps
  • PDF assessment report attached as evidence
  • HTML assessment report attached for easy viewing
  • CR category, priority, and assignment group auto-set based on cluster tier
~30 seconds
7
Approval Gate — Auto-Polling
Approval Gate
System continuously polls ServiceNow for Change Request approval. No human follow-up needed.
  • Polls ServiceNow API every 60 seconds for CR state changes
  • Auto-advances to next step when CR reaches "Approved" state
  • State machine pauses safely at this gate — no timeout, no data loss
  • Dashboard shows live CR status to the user
Automatic (waits for approval)
8
Dry Run Validation
Automated
Final preflight validation before committing to the upgrade.
  • Re-validates upgrade path is still available
  • Checks no new blockers appeared since pre-assessment
  • Verifies cluster state hasn't degraded during approval wait
  • Confirms all prerequisites still met
1–2 minutes
9
Execute Upgrade
Automated
System initiates the CVO-driven cluster upgrade and records the execution timestamp.
  • Patches ClusterVersion resource with target version
  • Records precise executedAt timestamp for audit trail
  • Updates ServiceNow CR with work notes: "Upgrade initiated at [timestamp]"
  • Transitions state machine to monitoring phase
~30 seconds to initiate
10
Real-Time Progress Monitoring
Automated
Continuous autonomous monitoring with 15-second polling — zero human babysitting required.
  • Polls ClusterVersion every 15 seconds for CVO progress percentage
  • Tracks operator health in real-time (available, degraded, progressing)
  • Monitors node readiness as nodes reboot during upgrade
  • Live dashboard shows progress bar, operator matrix, and node status
  • Updates ServiceNow CR with periodic work notes on progress
Cluster-paced (typically 30–90 min)
11
Smart Completion Detection
AI Powered
Upgrade is marked complete only when ALL three conditions are verified — prevents false completion.
  • Condition 1: ClusterVersion history shows target version confirmed
  • Condition 2: ALL ClusterOperators are available and not degraded
  • Condition 3: ALL nodes are in Ready state
  • Records precise completedAt timestamp
  • Calculates and records total upgrade duration
Automatic (triggers when all 3 conditions met)
12
Post-Assessment & Report Generation
AI Powered
AI generates comprehensive post-upgrade assessment with full timing, metrics, and health status.
  • PDF Report with: verified version, upgrade start/end timestamps, total duration
  • Operator health summary: total / available / degraded counts
  • Node health summary: total / ready counts
  • HTML Report with same data for web viewing
  • Both reports attached to ServiceNow CR
1–2 minutes
13
ServiceNow CR Closure
Automated
System auto-closes the Change Request with detailed close notes and all evidence attached.
  • Close notes include: upgrade start time, end time, total duration
  • Operator health status at completion: "X of Y operators healthy"
  • Node health status at completion: "X of Y nodes ready"
  • Post-assessment PDF and HTML attached as final evidence
  • CR state set to "Closed - Successful"
  • Complete audit trail preserved for compliance
~30 seconds
